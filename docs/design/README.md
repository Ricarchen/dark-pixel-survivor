# 设计文档索引

本目录保存目标独立游戏的设计；外部旧 Phaser 原型只作为隔离的历史验证资料引用。

## 交接入口

- [新模型交接与审计说明](./DESIGN_HANDOFF.md)：接手时先读。提供仓库边界、权威阅读顺序、最新确认摘要、当前未决问题、审计重点与工作方式。

## 目标游戏

- [目标游戏宏观设计](./TARGET_GAME_DESIGN.md)：产品设计的阅读起点。描述整体玩法循环、角色、武器、关卡、成长层级与内容生产单位。
- [详细设计决策账本](./GAME_ARCHITECTURE.md)：保存已确认细则、待定项、已废止规则和当前讨论位置。
- [角色技能进化网络设计报告](./systems/CHARACTER_EVOLUTION_NETWORK.md)：角色母路线、身份契约、开放式投资、多样节点结果、混合成长窗口、分层公开与融合的权威报告。
- [武器系统完整设计报告](./systems/WEAPON_SYSTEM.md)：武器系统的权威流程、来源限定 A、发现信息、继承矩阵、边界与数据要求。

## 设计治理

- [设计报告治理规范](./DESIGN_GOVERNANCE.md)：规定每份报告的状态、版本、必备章节、例外与验收标准。
- [设计追踪矩阵](./DESIGN_TRACEABILITY.md)：记录文档版本、决策依赖、下游影响、原型映射与待复核队列。

## 旧原型隔离区

- [旧原型边界说明](./legacy/README.md)：说明外部 Phaser 项目如何作为历史验证资料引用，并与本设计仓库隔离。

## 更新纪律

1. 宏观方向变化时，先更新 `TARGET_GAME_DESIGN.md`。
2. 对话中持续记录已确认、助手提案与未回答项；完成一个连贯章节或用户明确要求保存时，再启动一次文档批次。
3. 批次内先更新 `GAME_ARCHITECTURE.md` 的稳定编号，再同步对应系统报告与 `DESIGN_TRACEABILITY.md`。
4. 一批确认对应一次集中提交，不为每一句“同意”单独提交。
5. 旧原型中的规则不会自动进入目标设计，必须经过重新讨论和确认。
6. 文档确认不等于功能已实现。
